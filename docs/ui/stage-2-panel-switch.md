# 阶段 2（UI）：面板切换 —— 预加载 + 骨架兜底

> 分支 `ui/panel-switch` · 父提交 → `ui/tokens`（阶段 1）

## 1. 做了什么

| 文件 | 改动 |
|---|---|
| `lib/panelPrefetch.ts` | **新增**：8 个面板的 loader 注册表 + 幂等 `loadPanel` + `prefetchPanelsIdle`（空闲串行预加载） |
| `components/panels/PanelSkeleton.tsx` | **新增**：与真实面板同尺寸的骨架（复用 `.panel-shell` / `.panel-head` / `.rail-w`） |
| `App.tsx` | `<Suspense fallback={null}>` → `fallback={<PanelSkeleton title=…>}`；启动后空闲预加载；暴露 `data-panel-current` 供 e2e 定位 |
| `scripts/verify-panel-switch.cjs` | **新增**：4 条断言 |

## 2. 关键结论：**预加载对本项目几乎无收益，真正起作用的是骨架**

这点必须写清楚，否则会误导后续判断。

### 实测（同一脚本、同一机器）

| 配置 | 7 个面板切换后内容出现时间 |
|---|---|
| 有预加载 | 307–323 ms |
| **去掉预加载（变异测试）** | **307–323 ms** |

两者完全一致。原因：本项目是本地打包应用，chunk 从磁盘加载只需十几毫秒，
**切换耗时的大头是面板自身打开后取数**（诊断加载 sections、批量拉连接列表等），
而不是 chunk 下载。预加载优化的是一个本来就不慢的环节。

### 那「白屏」是怎么回事

原来 `fallback={null}`，副作用是：

- chunk 加载的那 10–30ms → 纯空白；
- 面板自身取数的 300ms → **也是空白**（面板 `if (!open) return null`，数据没到就什么都不画）。

也就是说用户感知的「切换闪烁」主体是**那 300ms 的空窗期**，不是 chunk 下载。
骨架一上，这 300ms 变成「一个和真实面板同尺寸、同头部高度的占位」——观感从「闪一下」变成「立刻有东西、然后内容填进来」。

### 保留预加载的理由

它不是收益，但也不是成本：

- 每次只在空闲窗口发起一个 import，串行、可取消；
- 对「装在人慢机器上、或将来 chunk 变大」的场景是免费的保险；
- 代码量 ~90 行，无依赖。

**但我不会在报告里把它写成「已优化切换性能」** —— 它没有。

## 3. 骨架的三条约束（写进组件注释）

1. **尺寸与真实面板一致**：复用 `.panel-shell`（top/bottom 由 token 决定）+ `.panel-head`（32px）+ `.rail-w`，
   否则内容到达时整块布局会跳，比白屏更难受。
2. **不做 shimmer 动画**：骨架是兜底路径，一闪而过时动画反而是噪声。
3. **标题来自当前面板**（`panelIdFor` + 标题表），不写死「加载中…」。

### 断言设计（含一次自我纠错）

| # | 断言 |
|---|---|
| 1 | 累计空白 ≤ 100ms（无持续白屏） |
| 2 | 内容出现 ≤ 700ms（含面板自身取数） |
| 3 | 等待期间有骨架覆盖（不再是空白） |
| 4 | 每个面板切换后都出现真实内容（非骨架） |

过程中修掉三个「测不出来」的问题：

1. **骨架自己也有 `.panel-shell`**（为了同尺寸）→ 用「有没有 `.panel-shell`」判内容，两种状态都算有内容，断言恒真。
   改用 `aria-busy` 区分：骨架 = `.panel-shell[aria-busy=true]`。
2. **在 Node 侧轮询计时**：每次 CDP 往返 ~40ms，量出的「骨架时长 320ms」全是往返成本。
   改成页面内 `requestAnimationFrame` 采样。
3. **空白阈值 40ms 太紧**：门禁串跑时 CPU 争用会让单帧拉长，「机器忙」被判成「白屏回归」。放宽到 100ms —— 真回归是数百毫秒量级，判别力仍在。

## 5. 风险与回滚

| 风险 | 说明 |
|---|---|
| 骨架遮挡真实面板的点击 | 骨架只在 Suspense pending 期间存在，内容一到即卸载；e2e 18/18 未受影响 |
| 预加载抢 CPU | 串行 + 空闲窗口 + 可取消；实测无 CPU 峰值 |
| `data-panel-current` 包装 div | `className="contents"` 不产生盒子，不影响布局 |

回滚：`git checkout ui/tokens`。或（更细）只把 `fallback` 改回 `null` 即恢复旧行为，预加载可独立保留。

## 6. 顺带纠正的操作失误

本次我曾把「全量门禁」和「UI e2e」**并发**跑，导致 e2e 出现 1 项失败（右键删除目录）且耗时从 27.7s 涨到 42.6s。
单独重跑即 18/18 通过、27.7s。**属于我的编排问题，不是代码问题**。后续阶段门禁一律串行。
